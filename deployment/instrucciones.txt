INSTRUCCIONES DE DESPLIEGUE — xkale-inventory
==============================================
Servidor:       Ubuntu / Debian (22.04 o superior)
Dominio:        xkale.inventory (LAN interna, HTTPS con certificado autofirmado)
Base de datos:  PostgreSQL en el mismo servidor (base xkaleinventory, usuario xkaledb)

Arquitectura en el servidor:
  nginx :443  ─┬─ /api/*  → uvicorn 127.0.0.1:8000 (servicio systemd xkale-inventory)
               └─ resto   → /var/www/xkale-inventory (frontend compilado)
  Código:  /opt/xkale-inventory      (copia gestionada por deploy.sh, no editar a mano)
  Config:  /opt/xkale-inventory/backend/.env   (se conserva entre despliegues)


PASO 1 — CLONAR EL REPOSITORIO
------------------------------
    sudo apt-get install -y git
    git clone https://github.com/cbuitron03/xkale-inventory.git ~/xkale-inventory
    cd ~/xkale-inventory


PASO 2 — CARGAR LA BASE DE DATOS (solo la primera vez)
------------------------------------------------------
Si la base xkaleinventory todavía está vacía, carga el backup incluido en el repo.
Hazlo con el mismo usuario que usará la app, para que las tablas queden a su nombre:

    psql -h 127.0.0.1 -U xkaledb -d xkaleinventory \
         -v ON_ERROR_STOP=1 --single-transaction -f Bckup_actualizado.sql

Si falla, no se aplica nada (la base queda vacía) y se puede reintentar.


PASO 3 — PRIMER DESPLIEGUE
--------------------------
    sudo bash deployment/deploy.sh

La primera vez el script crea /opt/xkale-inventory/backend/.env con una
SECRET_KEY generada y se detiene. Pon la contraseña de xkaledb:

    sudo nano /opt/xkale-inventory/backend/.env
      DATABASE_URL=postgresql://xkaledb:CONTRASEÑA@127.0.0.1:5432/xkaleinventory

(Si la contraseña tiene @ : / # % hay que codificarla:
 python3 -c "import urllib.parse; print(urllib.parse.quote('CLAVE', safe=''))")

Y vuelve a ejecutar:

    sudo bash deployment/deploy.sh

El script instala nginx, Python y Node 22, copia el código, crea el venv,
verifica la conexión a la base, compila el frontend, genera el certificado,
configura nginx y systemd, y al final comprueba que la API responde.


PASO 4 — NOMBRE xkale.inventory EN LA LAN (DNS)
-----------------------------------------------
El servidor debe tener IP fija (reserva DHCP o IP estática): 192.168.2.249.

Opción A (recomendada) — DNS interno. En el DNS que usan los equipos
(Windows Server DNS / router / firewall):
    Zona directa:  inventory
    Registro A:    xkale  →  192.168.2.249
  (Windows Server: Administrador DNS → Zonas de búsqueda directa → Nueva zona
   "inventory" → Nuevo host (A) "xkale" con IP 192.168.2.249)

Opción B — archivo hosts en cada equipo (temporal o equipos sueltos):
    Windows: C:\Windows\System32\drivers\etc\hosts   (como administrador)
    macOS:   /etc/hosts
    línea:   192.168.2.249  xkale.inventory

Comprobar desde un cliente:  nslookup xkale.inventory   (o ping xkale.inventory)
Al ser un dominio interno, escribe la dirección completa con https:// la
primera vez; si no, el navegador puede tratarla como una búsqueda.


PASO 5 — CONFIAR EN EL CERTIFICADO (quita "Conexión no segura")
---------------------------------------------------------------
deploy.sh crea una CA interna de Xkale y firma con ella el certificado del
servidor. En los clientes se instala SOLO la CA, una única vez:
    /etc/nginx/ssl/xkale-ca.crt
    descargable en:  http://192.168.2.249/xkale-ca.crt

Equipos gestionados por Intune (recomendado, llega a todos a la vez):
  Intune → Dispositivos → Configuración → Crear → Windows 10 y posterior →
  Plantillas → "Certificado de confianza" → subir xkale-ca.crt →
  Almacén: "Raíz de equipo" → asignar a "Todos los dispositivos".
  (Para macOS: mismo perfil "Certificado de confianza" en la plataforma macOS.)

A mano:
  Windows: doble clic en xkale-ca.crt → Instalar certificado → Equipo local →
           "Entidades de certificación raíz de confianza"
  macOS:   sudo security add-trusted-cert -d -r trustRoot \
             -k /Library/Keychains/System.keychain xkale-ca.crt
  Ubuntu:  sudo cp xkale-ca.crt /usr/local/share/ca-certificates/ && sudo update-ca-certificates

Cierra y vuelve a abrir el navegador después de instalarla. Chrome y Edge usan
el almacén del sistema; Firefox en Windows también si está activada la
política "enterprise roots" (activada por defecto en versiones recientes).

El certificado del servidor dura 825 días; deploy.sh lo renueva solo cuando le
faltan menos de 30 días, con la misma CA, sin tocar los clientes.
Si el servidor cambia de IP: sudo rm /etc/nginx/ssl/xkale.inventory.crt y
volver a ejecutar deploy.sh.


ACTUALIZAR LA APLICACIÓN (automático)
-------------------------------------
deploy.sh instala el timer "xkale-autodeploy": cada 2 minutos revisa GitHub y,
si master tiene commits nuevos, hace git pull en el clon (~/xkale-inventory)
y ejecuta deploy.sh. Basta con hacer push a master; se publica en ~2-5 minutos.

  Ver qué se desplegó / errores:   journalctl -u xkale-autodeploy -n 50
  Próxima revisión:                systemctl list-timers xkale-autodeploy.timer
  Forzar una revisión ya:          sudo systemctl start xkale-autodeploy
  Desactivar:                      sudo systemctl disable --now xkale-autodeploy.timer
  Reactivar:                       sudo systemctl enable --now xkale-autodeploy.timer

Si un commit falla al desplegar, la app sigue con la versión anterior y ese
commit no se reintenta en cada ciclo: se reintenta con el siguiente push.
No edites archivos dentro del clon del servidor: con cambios locales el
git pull automático se detiene (el log lo indica).

Manual (sigue funcionando igual):
    cd ~/xkale-inventory
    git pull
    sudo bash deployment/deploy.sh

El .env del servidor no se toca al actualizar.


COMANDOS ÚTILES
---------------
Estado del backend:        systemctl status xkale-inventory
Logs en tiempo real:       journalctl -u xkale-inventory -f
Reiniciar el backend:      sudo systemctl restart xkale-inventory
Probar la API:             curl -k https://127.0.0.1/api/
Documentación de la API:   https://xkale.inventory/api/docs
Recargar nginx:            sudo nginx -t && sudo systemctl reload nginx
